02 — Casos

Casos de engenharia

Trabalho feito para clientes não vira repositório público. Aqui ficam as decisões, no formato de ADR: contexto, decisão e resultado. Clientes identificados apenas pelo setor.

ADR-01

De timeout a 2,5 s em antecipação de recebíveis

GFT Brasil · 2023–2024Setor bancário · consultoria de soluções
RedisMySQLAPI GatewayPerformance
Contexto

O sistema corporativo de antecipação de recebíveis estourava o timeout do API Gateway: mais de 12 segundos por requisição em lotes grandes de boletos.

Decisão

Identifiquei o gargalo na persistência relacional e troquei o MySQL por uma camada de cache Redis para os dados de simulação, com TTL de 24 horas.

Resultado2,5 s

tempo máximo por requisição. Lotes de até 2.000 boletos simultâneos, sem timeouts e com 100% das transações concluídas.

ADR-02

Migração para Java 25 e Spring Boot 4.1.1 com agentes de IA

GFT Brasil · 2026–atualSetor bancário · abertura de contas
Java 25Spring Boot 4.1.1OpenRewriteMongoDBAgentes Claude
Contexto

Os serviços de abertura de conta de um banco precisavam migrar de versão sem comprometer segurança nem consistência arquitetural.

Decisão

Decompus o escopo em tarefas com contratos claros (SDD). Agentes Claude e OpenRewrite geram o código; eu reviso criticamente e controlo o que entra na branch principal.

Resultado8 de 16

serviços do escopo migrados por mim; os demais revisados e integrados sob o mesmo gate na branch principal.

ADR-03

Antifraude em .NET com arquitetura hexagonal

Officecom · 2024–2026Setor de apostas esportivas · regulação
.NETC#HexagonalCode review
Contexto

Serviço de missão crítica para validação de dados pessoais e antifraude, exigido pela nova regulamentação brasileira de apostas esportivas.

Decisão

Monólito em arquitetura hexagonal em .NET, com o domínio isolado das integrações. Liderei 3 devs (1 pleno, 2 júniores), com decomposição de escopo e code review rigoroso.

Resultado750/dia

novos usuários validados por dia, além de 200 revalidações biométricas diárias.

ADR-04

Do IBM CastIron para Kafka: faturas quase em tempo real

GFT Brasil · 2021–2022Setor de planos de saúde · GCP
KafkaKSQLJava 15GCPSalesforce
Contexto

A geração de faturas de clientes dependia de rotinas em lote sobre um middleware legado (IBM CastIron), com alto custo de licenciamento.

Decisão

Migrei a integração para uma arquitetura orientada a eventos com Apache Kafka e KSQL. Um consumidor Kafka em Java 15 consulta os dados de forma assíncrona, enriquece via APIs internas e envia ao Salesforce.

ResultadoLote → evento

Faturas geradas quase em tempo real, no lugar das rotinas em lote, e custo de licenciamento do IBM CastIron eliminado.
